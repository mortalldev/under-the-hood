## TL;DR

<Term id="backtracking" /> is DFS over a tree of partial solutions: **choose** an option, **explore** recursively, **un-choose** to restore state, try the next option. It enumerates exponentially many candidates, so the craft is in <Term id="pruning" /> — cutting branches that cannot lead to (better) answers — and in making the undo step exact.

## Visual model

```text
                        []
          /              |            \
        [1]             [2]           [3]          each node = one partial solution
       /    \            |                         subsets: every node is an answer
   [1,2]   [1,3]       [2,3]                       permutations: only leaves of depth n
     |
  [1,2,3]
```

## Mechanism

The recursion keeps one shared `path`. Every push is matched by a pop after the recursive call returns, so when control comes back to a frame, `path` is exactly what that frame expects. Watch the call stack and the path grow and shrink:

<SubsetsViz />

`start` index prevents duplicates like `[2, 1]` after `[1, 2]`: each frame only chooses elements to the right of the last chosen one.

## Code

```ts
// Permutations: track which elements are used
function permutations(nums: number[]): number[][] {
  const out: number[][] = [], path: number[] = [];
  const used = new Array<boolean>(nums.length).fill(false);
  const go = () => {
    if (path.length === nums.length) { out.push([...path]); return; }
    for (let i = 0; i < nums.length; i++) {
      if (used[i]) continue;
      used[i] = true; path.push(nums[i]);
      go();
      path.pop(); used[i] = false;
    }
  };
  go();
  return out;
}

// Combination Sum (reuse allowed) with pruning on a sorted array
function combinationSum(cands: number[], target: number): number[][] {
  cands.sort((a, b) => a - b);
  const out: number[][] = [], path: number[] = [];
  const go = (start: number, remaining: number) => {
    if (remaining === 0) { out.push([...path]); return; }
    for (let i = start; i < cands.length; i++) {
      if (cands[i] > remaining) break;           // prune: sorted, so the rest are too big
      path.push(cands[i]);
      go(i, remaining - cands[i]);               // i, not i + 1: reuse allowed
      path.pop();
    }
  };
  go(0, target);
  return out;
}

// N-Queens: O(1) conflict checks with column and diagonal sets
function solveNQueens(n: number): number {
  const cols = new Set<number>(), d1 = new Set<number>(), d2 = new Set<number>();
  let count = 0;
  const place = (r: number) => {
    if (r === n) { count++; return; }
    for (let c = 0; c < n; c++) {
      if (cols.has(c) || d1.has(r - c) || d2.has(r + c)) continue;
      cols.add(c); d1.add(r - c); d2.add(r + c);
      place(r + 1);
      cols.delete(c); d1.delete(r - c); d2.delete(r + c);
    }
  };
  place(0);
  return count;
}
```

## When to use / when not to

**Recognition signals**
- "Return **all** subsets / permutations / combinations / partitions / placements".
- Constraint satisfaction: N-Queens, Sudoku, word search on a board.
- Small n (≤ ~15–20) — the constraints themselves say exponential is expected.

**When not to**
- You need the **count** or the **best** value, not the list, and subproblems repeat → DP / memoization.
- A greedy choice is provably safe → greedy.
- n is large and no strong pruning exists → reconsider the model.

## Trade-offs

| Problem | Output size | Time |
| --- | --- | --- |
| Subsets | 2ⁿ | O(n · 2ⁿ) |
| Permutations | n! | O(n · n!) |
| Combinations C(n, k) | C(n, k) | O(k · C(n, k)) |
| N-Queens | ≤ n! | far less with pruning |

## Senior nuance

- **Duplicates in input** (Subsets II, Permutations II): sort, then skip `nums[i] === nums[i − 1]` when the previous equal element was **not** chosen at this level (`i > start` for subsets, `!used[i − 1]` for permutations).
- **Copy on record**: `out.push(path)` stores a reference to an array you will keep mutating — every answer ends up empty. Push `[...path]`.
- **Undo must be exact**: restore every piece of state you changed (grid cell, counters, sets), in reverse order. Bugs here look like "works on the first branch only".
- **Memoize when the state is small**: if the future depends only on (index, remaining), the problem is DP in disguise (Word Break, Partition Equal Subset Sum).

## Interview questions

<QA q="Word Search on a grid — how do you avoid reusing a cell?" level="mid">
Mark the cell (e.g. temporarily replace it with '#') before recursing into neighbours and restore it after. That is the un-choose step. Prune immediately when the current cell does not match the next letter. Worst case O(R · C · 4 · 3^(L−1)).
</QA>

<QA q="Subsets II (input has duplicates): how do you avoid duplicate subsets?" level="mid">
Sort first. In the loop of a frame, skip `nums[i]` if `i > start` and `nums[i] === nums[i − 1]`: choosing the second equal value at the same depth would recreate a branch identical to the one that chose the first.
</QA>

<QA q="When does backtracking become DP?" level="senior">
When the result of exploring from a state depends only on a small summary of the path (not the whole path) and the same summaries recur. Then cache results per state; the recursion tree collapses into a DAG of states. Example: Word Break's state is just the start index.
</QA>
