## TL;DR

<Term id="union-find" /> (disjoint set union) maintains a partition of elements into groups under two operations: `find(x)` → the group's representative, and `union(a, b)` → merge two groups. With <Term id="path-compression" /> and union by rank, both run in O(α(n)) amortized — α is the inverse Ackermann function, which is at most 4 for any input that fits in the universe. It is the tool for **dynamic connectivity** when edges only get added.

## Visual model

Each group is a tree; every node points to its parent, and the root points to itself. Two elements are connected iff they have the same root.

```text
parent: 1→1  2→1  3→1  4→3      find(4): 4 → 3 → 1 (root)
        5→5  6→5                after compression: 4 → 1 directly
```

## Mechanism

- `find` walks parent pointers to the root and, on the way back, **re-points every visited node directly to the root**. Later finds on that path are one hop.
- `union` finds both roots; if equal, the edge would create a cycle (that is Kruskal's and "redundant connection"'s test). Otherwise it hangs the **shorter** tree under the taller one (rank ≈ height upper bound), keeping trees O(log n) tall even before compression.

## Code

```ts
class DSU {
  parent: number[];
  rank: number[];
  count: number;                                  // number of components
  constructor(n: number) {
    this.parent = Array.from({ length: n }, (_, i) => i);
    this.rank = new Array(n).fill(0);
    this.count = n;
  }
  find(x: number): number {
    let root = x;
    while (this.parent[root] !== root) root = this.parent[root];
    while (this.parent[x] !== root) {             // iterative path compression
      const next = this.parent[x];
      this.parent[x] = root;
      x = next;
    }
    return root;
  }
  union(a: number, b: number): boolean {
    let ra = this.find(a), rb = this.find(b);
    if (ra === rb) return false;
    if (this.rank[ra] < this.rank[rb]) [ra, rb] = [rb, ra];
    this.parent[rb] = ra;
    if (this.rank[ra] === this.rank[rb]) this.rank[ra]++;
    this.count--;
    return true;
  }
}

// Accounts Merge, Number of Provinces, Redundant Connection: union along edges, then group by find()
```

## When to use / when not to

**Recognition signals**
- "Are x and y connected?" asked repeatedly while edges are **added**.
- Count components, detect the edge that closes a cycle, merge accounts/emails, group equivalent items ("a == b" constraints).
- Kruskal's MST.

**When not to**
- Edges are **deleted** → union-find cannot split; use offline reversal (process deletions backwards as additions) or dynamic connectivity structures.
- You need paths, distances or the actual route → BFS/DFS.
- One-off connectivity question on a static graph → a single BFS/DFS is just as good and simpler.

## Trade-offs

| Variant | find / union | Notes |
| --- | --- | --- |
| Naive parent pointers | O(n) worst | chains form easily |
| Union by rank/size only | O(log n) | trees stay shallow |
| Path compression only | O(log n) amortized | simple, usually enough |
| Both | O(α(n)) amortized | effectively constant |

## Senior nuance

- **Recursive `find` with compression** is a one-liner but recursion depth can reach n before the first compression on adversarial input; the iterative two-pass version above avoids that.
- **Weighted union-find** stores, on each edge, a relation to the parent (ratio, parity, offset). Path compression must combine the weights. It solves "Evaluate Division" and bipartite-with-constraints problems.
- **Union by size** (track component sizes) is as good as rank and gives you sizes for free — useful for "largest component" questions.
- **Map arbitrary keys** (emails, coordinates) to integer ids first; a `Map<string, number>` keeps the DSU array-based and fast.

## Interview questions

<QA q="Why does union by rank keep trees O(log n) tall?" level="senior">
A root's rank increases only when merging two trees of equal rank, so a tree of rank r has at least 2^r nodes (induction). With n nodes, r ≤ log₂ n, and height ≤ rank. Path compression then shrinks heights further, giving the α(n) amortized bound.
</QA>

<QA q="Redundant Connection: return the edge that, if removed, leaves a tree." level="mid">
Process edges in order with union-find. The first edge whose endpoints already share a root closes a cycle — return it. O(n α(n)).
</QA>

<QA q="Satisfiability of equality equations (a==b, b!=c, …)." level="mid">
Union all `==` pairs first, then check each `!=` pair: if both sides have the same root, the system is unsatisfiable. Order matters: all unions before any inequality check.
</QA>
