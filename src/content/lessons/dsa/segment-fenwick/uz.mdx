## TL;DR

Array oʻzgaradi **va** oraliq agregatlari kerak boʻlganda prefix sum (O(n) yangilash) ham, qayta hisoblash (O(n) soʻrov) ham ishlamaydi. <Term id="fenwick-tree" /> ~10 qatorda O(log n) nuqtaviy yangilash va prefix sum beradi; **segment tree** har qanday assotsiativ agregat (sum, min, max, gcd) uchun O(log n) beradi, lazy propagation bilan esa **oraliq yangilanishlarini** ham hal qiladi.

## Vizual model

```text
Fenwick: tree[i] (i − lowbit(i), i] ni qoplaydi    lowbit(i) = i & −i (eng kichik 1-bit)
i (binary)  qoplaydi
 1  0001    [1, 1]
 2  0010    [1, 2]
 3  0011    [3, 3]
 4  0100    [1, 4]
 6  0110    [5, 6]
 8  1000    [1, 8]

prefix(7) = tree[7] + tree[6] + tree[4]    (7 → 6 → 4 → 0: har safar eng kichik bitni olib tashlash)
```

## Mexanizm

- **Soʻrov** `prefix(i)`: `tree[i]`ni qoʻshing, keyin `i − lowbit(i)`ga — undan oldingi blok oxiriga sakrang. Sakrashlar soni i dagi 1-bitlar soniga teng: ≤ log₂ n.
- **Yangilash** `add(i, Δ)`: i pozitsiyasini oʻz ichiga olgan har bir blok oʻzgarishi kerak. Ular `i, i + lowbit(i), …` — i ni qoplaydigan keyingi blokka koʻtarilish. Bu ham ≤ log₂ n.

Qurishni (har bir `add` koʻtariladi), keyin prefix soʻrovini (har qadam bitni olib tashlaydi) kuzating:

**Segment tree** `[l, r]` agregatini node'da saqlaydi va uni `[l, mid]` va `[mid + 1, r]` ga boʻladi. Har qanday soʻrov oraligʻi O(log n) ta toʻliq qoplangan node'ga boʻlinadi; yangilash root'dan bargacha bitta yoʻldagi O(log n) node'ni oʻzgartiradi.

## Kod

```ts
class Fenwick {
  private t: number[];
  constructor(n: number) { this.t = new Array(n + 1).fill(0); }       // 1 dan indekslangan
  add(i: number, delta: number) { for (; i < this.t.length; i += i & -i) this.t[i] += delta; }
  prefix(i: number) { let s = 0; for (; i > 0; i -= i & -i) s += this.t[i]; return s; }
  range(l: number, r: number) { return this.prefix(r) - this.prefix(l - 1); }  // kiritilgan, 1 dan
}

class SegmentTreeMin {
  private t: number[];
  constructor(private n: number, a: number[]) {
    this.t = new Array(2 * n);
    for (let i = 0; i < n; i++) this.t[n + i] = a[i];                // barglar n..2n−1 da
    for (let i = n - 1; i > 0; i--) this.t[i] = Math.min(this.t[2 * i], this.t[2 * i + 1]);
  }
  set(i: number, v: number) {
    for (this.t[i += this.n] = v; i > 1; i >>= 1) this.t[i >> 1] = Math.min(this.t[i], this.t[i ^ 1]);
  }
  query(l: number, r: number) {                                       // [l, r) dagi min
    let res = Infinity;
    for (l += this.n, r += this.n; l < r; l >>= 1, r >>= 1) {
      if (l & 1) res = Math.min(res, this.t[l++]);
      if (r & 1) res = Math.min(res, this.t[--r]);
    }
    return res;
  }
}
```

## Qachon ishlatiladi / ishlatilmaydi

**Tanib olish signallari**
- Aralash nuqtaviy yangilanishlar va oraliq soʻrovlari ("Range Sum Query - Mutable").
- Inversiyalarni sanash / "count of smaller numbers after self": oʻngdan aylaning, **rank**'lar (coordinate compression qilingan qiymatlar) ustidagi Fenwick tree'dan soʻrang, keyin qoʻshing.
- Yangilanishli oraliq min/max; oraliqqa qoʻshish + oraliq yigʻindisi (lazy segment tree).

**Qachon kerak emas**
- Statik array → prefix sum (yigʻindi) yoki sparse table (min/max, O(1) soʻrov).
- Faqat global min/max oʻzgaradi → heap.
- Boshqa tuzilmali offline soʻrovlarga Mo algoritmi yoki chekka boʻyicha saralash mos kelishi mumkin.

## Trade-off'lar

| Tuzilma | Yangilash | Soʻrov | Oraliq yangilash | Agregatlar | Kod hajmi |
| --- | --- | --- | --- | --- | --- |
| Prefix sum | O(n) | O(1) | O(n) | teskari qilinadigan (sum) | juda kichik |
| Fenwick | O(log n) | O(log n) prefix | ikki daraxt bilan | teskari qilinadigan (sum, xor) | ~10 qator |
| Segment tree | O(log n) | O(log n) | O(log n) lazy | har qanday assotsiativ | 30–60 qator |
| Sparse table | qayta qurish | O(1) | — | idempotent (min, max, gcd) | kichik |

## Senior nuance

- **Fenwick oraliq soʻrovlari uchun teskari qilinuvchanlikni talab qiladi** (`prefix(r) − prefix(l−1)`), shuning uchun min/max oraliqlari uchun segment tree kerak.
- **Coordinate compression** katta yoki siyrak qiymatlarni indeks sifatida ishlatishdan oldin 1..k ga aylantiradi — inversiyalarni sanash uchun standart.
- **Iterative pastdan-yuqoriga segment tree'lar** (yuqoridagidek) ixcham va tez; recursive'larini lazy propagation bilan kengaytirish osonroq.
- Production'da xuddi shu gʻoya agregatlangan B-tree node'lari yoki materializatsiya qilingan rollup'lar sifatida uchraydi; interview kutubxonani emas, mexanizmni tekshiradi.

## Interview savollari

<QA q="Count of Smaller Numbers After Self O(n log n) da." level="senior">
Qiymatlarni 1..k rank'larga coordinate compression qiling. Oʻngdan chapga aylaning: nums[i] uchun javob — fenwick.prefix(rank[i] − 1) (oʻngda allaqachon koʻrilgan kichikroq qiymatlar soni); keyin fenwick.add(rank[i], 1). Indekslarni kuzatuvchi merge sort — muqobil.
</QA>

<QA q="Nega Fenwick yangilanishi O(log n)?" level="mid">
Har qadam i ga lowbit(i) ni qoʻshadi, bu eng kichik 1-bitni kamida bir pozitsiya chapga suradi. Koʻpi bilan log₂ n qadamdan keyin i n dan oshadi. Xuddi shu bit dalili soʻrovni ham chegaralaydi: har qadam bitta 1-bitni tozalaydi.
</QA>

<QA q="'[l, r] dagi har bir elementga v qoʻshish' va '[l, r] boʻyicha yigʻindi'ni qanday qoʻllab-quvvatlaysiz?" level="senior">
Lazy propagation'li segment tree: toʻliq qoplangan node'da kutilayotgan qoʻshimchani saqlang va uni faqat keyingi amal chuqurroq borishi kerak boʻlgandagina bolalarga uzating. Muqobil: difference array ayniyatidan foydalanib ikki Fenwick tree (biri i koeffitsiyenti uchun, biri konstantalar uchun).
</QA>
